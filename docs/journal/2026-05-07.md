## K. 学んだこと (本セッション)

1. **🚨 Codex のサンドボックス制限**: `~/.codex/` 配下への書き込みが `Operation not permitted` で阻止される。 staged は `~/Desktop/.tmp/hatch-pet-<id>/package/<id>/` に残るので、 ユーザー側で `cp` 代行配置すれば良い。
2. **🚨 spritesheet RGBA 必須**: RGB で保存すると Codex Desktop App はペット一覧から除外する。 Pillow 保存時は `RGBA` mode 維持 + `lossless=True` 推奨。
3. **Codex の image_gen は実用品質**: 抽象 chibi キャラを 9 ポーズ × 8 frame で生成 + 透過化 + 72 frame atlas 化までを 1 タスクで完遂 (149K tokens で約 5 分)。 Pillow 自作の stick figure とは比較にならない品質。
4. **PR merge 監視 cron**: GitHub PR の merge 状態は `gh pr view --json state,mergedAt` で取得可能。 LaunchAgent + macOS notification で自動化できる。
5. **codex update は brew cask 経由**: stable channel のみ追従、 alpha は GitHub release から手動 install が必要。
6. **codex MCP server 化**: `codex mcp-server` で Codex CLI 自体を MCP server として動かす機能あり。 Claude Code から `Called codex` ネイティブ表示で呼び出し可能。
7. **VNC 真っ黒問題 (macOS 26)**: `screensharingd` が TCC Screen Recording 権限を持っていないと、 VNC 接続成功しても画面 capture 失敗で真っ黒。 別途 sudo + 設定 UI で許可必要 (今回は保留)。
8. **「家」 vs 「氏」 の呼称感覚**: ミニマリスト思想で「家」 (持ち物)を否定、 「氏」 (血縁・系譜) を肯定する仲氏の語感。 「源氏」 のように個人を氏族名で呼ぶ感覚。

### G. plist に env override 追加 (Mac 再起動後の自動起動を保証)

setup が書いた plist には env override が含まれず、 Mac 再起動 → KeepAlive で再起動した時にガードに当たって失敗する。 **env override を追加**:

```xml
<key>EnvironmentVariables</key>
<dict>
    <key>BRIDGE_PORT</key>
    <string>8765</string>
    <key>BRIDGE_HOST</key>
    <string>0.0.0.0</string>
    <key>npm_config_@anthropic-ai:registry</key>
    <string>https://registry.npmjs.org/</string>
</dict>
```

→ Mac 再起動後も Bridge Server が自動起動する状態で、 ガード本体は触らない (5/6 追補 9 のガード = `@anthropic-ai/claude-code` 経由の global install 阻止という本来目的は維持)。

### 学んだこと

1. **5/6 追補 9 のガードは scope 単位なので副作用が出る**: `@anthropic-ai/claude-code` を阻止する目的で `@anthropic-ai:registry=http://localhost:1` を設定すると、 同 scope の **他パッケージ** (例: `@anthropic-ai/claude-agent-sdk`) も巻き添えになる。 今後のためには「特定パッケージ名のみブロック」 する方法を検討する余地あり (ただし npm にはそういう機能なし、 やるなら .npmrc で別パッケージごとに registry override が必要)。
2. **env 変数で process scope override が最もクリーン**: ガード本体を触らず、 npx 1 回 + plist 内 env で永続化できる。 launchd は EnvironmentVariables を渡せるので相性が良い。
3. **CC Pocket の Connection refused はキャッシュ表示**: server 側が完全に動いていても、 アプリ側の「前回失敗状態」 を表示することがある。 「開始」 再タップ or リロードボタンで解決。
4. **VNC 真っ黒問題の代替として CC Pocket が完璧**: 5/7 13:00 から保留中の TCC 権限問題は、 CC Pocket (テキスト UI) で完全代替可能。 視覚的なものは別途 VNC 必要、 操作系は CC Pocket で十分。
