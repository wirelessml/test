### 5/20 6:30 — 根本調査

#### 誤読 1 (即訂正): gci_admin Desktop が「一掃された」

`gci_admin\Desktop` 内が空 (`desktop.ini` のみ) を見て「Storage Sense / Defender 等で削除された」と推測。 → **誤り**。 SSH の cwd が `C:\Users\gci_admin\` (home root) で、scp は home root に着地していた。Desktop は元から空、ファイルは別の場所に存在していた (`C:\test\` リポジトリクローン内に紛れていた)。

#### 真因 1: Job Object ハード終了 (本命)

Windows Scheduled Task は、Action から起動した子プロセスを **Job Object に登録** → タスク "完了" 時に Job Object 内の全プロセスを **ハード終了**。bat → cmd → codex.cmd remote-control の全部が連鎖して即死。

直接 `cmd /c run-codex-remote.bat` を ssh から foreground で叩くと動く (Job Object 外) のはこのため。22:47 の最初のテストが偶然うまく見えたのも、Start-Sleep 12 の窓内で起動と即死がたまたま重なっていた可能性が高い。

#### 真因 2: タスク RunLevel = Limited (補助的)

codex の `config.toml` に `[windows] sandbox = "elevated"` 設定あり。タスクの Principal が `gci_admin Interactive Limited` だと elevated 要求と矛盾。Highest に変更で解消。

### 5/20 6:42 — 解決策の確定

1. **`AllowHardTerminate = False`** (Job Object ハード終了を回避)
2. **`run-codex-remote.bat` を `start /MIN cmd /c` で独立 process group** 起動
3. **タスク RunLevel = Highest** (elevated sandbox 要求と整合)
4. **watchdog 待機時間 5s → 10s** (codex 起動初期化を捕捉)

検証:
```
=== before ===   PID 3632
=== kill ===     OK
=== fire watchdog ===  schtasks 発火
=== after 12s ===  PID 28760 復活 (1 秒以内)
watchdog log:    DOWN → UP (PID 28760)
```

完全動作確認。

## 学んだこと / 気づき

### 1. Windows Scheduled Task の Job Object ハード終了

`AllowHardTerminate = $true` (デフォルト) だと、タスクの Action から生まれた子プロセスがすべて Job Object に登録され、タスクが「完了した」時点でハード終了される。長時間動く daemon-like なプロセスを起動する場合、`$false` 必須。または `start` / `Start-Process` で **独立 process group** に逃がす。両方併用が安全。

### 2. Codex CLI Windows 退行 (0.131)

OpenAI の `@openai/codex` パッケージは 0.131.0 で `codex remote-control` (app-server daemon lifecycle) を **Unix 専用に変更**。Windows ユーザーが `npm install -g @openai/codex@latest` で更新すると **iPhone Codex App から接続不可になる**。

**回避策**: Windows 機は `@openai/codex@0.130.0` でピン留め。`package.json` の semver は `0.130.0` 固定推奨。

### 3. 「重要ファイルをデスクトップに置かない」原則

`C:\Users\<user>\Desktop\` および `C:\test\` (作業リポジトリ) は:
- ユーザーが Explorer から誤削除可能
- Storage Sense / OneDrive 同期対象
- リポジトリ整理時 (`git clean -fd`) で巻き添え

運用スクリプトは `C:\ProgramData\<app>\` 等の **システム領域**に置く。SYSTEM/Administrators フルアクセス、Users 読込のみ、自動同期外。

### 4. 推測 → 訂正の連鎖

朝の調査で 3 回推測ミスして仲氏指摘で訂正:
- 「Desktop が Storage Sense で一掃」→ SSH cwd と scp 着地点の問題
- 「ProgramData に移そう (最初の提案)」→ SSH cwd 不明確で `C:\test\` に置き直してしまった
- 「`C:\test\` で十分」→ 仲氏「デスクトップには置かないように」で ProgramData に再移行

**仲氏の問題提起は構造的に正しい**: ファイル配置は「触られない場所」を選ぶのが原則。

### 5. SHub Reaper ≠ ゼロデイ

「Mac の常識が完全に覆った」は煽り。実態は infostealer ファミリーの最新変種、感染にはユーザー操作 (偽インストーラ実行) が必要。「macOS 標的の本格的 infostealer が量産化」が正確。
