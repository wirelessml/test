### X 投稿の解決 ①: M5 MacBook Air の Wi-Fi 不具合（松村太郎 @taromatsumura）

- 症状: M5 MacBook Air が Wi-Fi 接続はできるのにインターネットが通らない。自宅 Buffalo/NEC・大学 Cisco すべて NG、iPhone テザリングは OK。
- スレッド精読 + 裏取りの結果、**N1 チップ × コンテンツフィルタ系ネットワーク拡張**の相性問題の線が濃厚と判断。
- **Apple は macOS Tahoe 26.4.1（2026-04-09）で「M5 機がコンテンツフィルタ拡張使用時に 802.1X Wi-Fi へ繋がらない不具合」を修正済み**（公式リリースノートで確認）。
- 提示した切り分け: `sw_vers` で版確認 → 26.4.1+ に更新 → **セーフモード起動で一発切り分け**（拡張無効化でネットが通れば犯人は拡張）→ `systemextensionsctl list` + 設定>ネットワーク>「フィルタ」で特定・削除（大学 Cisco 網なら **Cisco Secure Client** が最有力容疑）。
- @minimalistneko 向けの返信案（セーフモード一発切り分け推し）を 3 パターン作成（投稿は仲氏判断）。

### masu-p55: Codex Desktop App 発見 + 残骸の再起動削除タスク

- **🚨 教訓**: 最初 Codex Desktop App を「アンインストールレジストリ / Program Files / winget」で探して「未インストール」と誤判定 → 仲氏「Windows ストア経由で入ってない？」の指摘で **`Get-AppxPackage` で発見**（`OpenAI.Codex` 26.527.3378.0）。**MSIX/Store アプリは従来の検出法に出ない**。
- Store 更新は **CIM `UpdateScanMethod`** で発火（winget は id 指定で掴めない）。
- 224MB 残骸（`.codex-0T2poKJG`）は Defender がハンドル保持で削除不可（昇格 + Defender 除外でも不可）→ **次回再起動で自動削除するワンショットタスク `CleanupCodexStaging`（SYSTEM/起動時、Defender 除外を先に追加してから削除し自己消滅）**を仕込んだ。詳細は @docs/machines/masu-p55.md。

### しゅん先生 PC: Codex 削除→再インストール の遠回り → Computer Use 有効化

1. 仲氏「Codex デスクトップアプリを削除して、再インストール」→ SSH で `Remove-AppxPackage` 実行。
2. **削除と同時に Windows がペイロードを GC**し、`Add-AppxPackage -Register` の再登録元（AppxManifest.xml）が消失 → 再登録失敗。
3. winget msstore 再インストールも **0x80073CF6** で失敗（残留 AppData クリア後も、wirel の対話セッション内でも、再起動後でも同じ）。
4. **OpenAI は Windows 版 Codex を Store 専売**（スタンドアロン無し、GitHub issue #13993 で確認）と判明 → SSH 単独再インストールは原理的に不可。
5. **復旧**: wirel がログオン中だったので、**対話セッションに Microsoft Store の Codex ページを開く**（Interactive ログオン型スケジュールタスク + `Start-Process`）→ 仲氏が再起動 + Store「入手」→ **正規に再インストール成功**（`Get-AppxPackage` REGISTERED, Status=Ok, manifest present で検証）。
6. その後 Computer Use プラグインの導入で「プラグインをインストールできませんでした」→ **Desktop App ログを SSH で精査** → **真因 = `~/.codex/config.toml` が読み取り専用**で `failed to persist installed plugin config: アクセスが拒否されました (os error 5)`。
7. **`attrib -R config.toml`（バックアップ後に解除）→ 再インストール成功 → アプリ再起動で `computer-use native pipe startup ready`**（helper 警告解消）。🎉 Windows Computer Use 有効化完了。
8. 副作用: config が書き込み可になり Desktop App が起動時に **`remote_control = true` を削除**（バックアップ済）。以降は Desktop App 純正 Remote Connections が稼働（3 connections）に移行。

詳細・各種ログ・コマンドは @docs/machines/shun-sensei-pc.md の「Codex Desktop App (Microsoft Store / MSIX)」セクションに永続化。

## 学んだこと / 気づき（再発防止）

1. **🚨 Store/MSIX アプリは `Get-AppxPackage` でしか見えない**。レジストリ / Program Files / winget id で探すと「未インストール」と誤判定する。最初にこれで遠回りした。
2. **🚨 Store/MSIX アプリを SSH から削除してはいけない**。削除はできるが再インストールが **Store GUI（対話セッション）必須**で、SSH (Session 0) からは 0x80073CF6 で不可。削除は壊れた半状態を残す。今回最大の遠回りの原因。
3. **Codex のプラグイン install 失敗 = `~/.codex/config.toml` の読み取り専用が真因のことがある**（`os error 5` / アクセス拒否）。`attrib -R` で解決。ログ（`...\LocalCache\Local\Codex\Logs\...\codex-desktop-*.log`）に明確に出る。
4. **対話セッションで GUI/MSIX を動かす技**: `New-ScheduledTaskPrincipal -UserId <user> -LogonType Interactive` のタスクを `Start-ScheduledTask` すると、ログオン中ユーザーのセッションで実行できる（パスワード不要）。Store ページを開く・アプリ再起動・winget 等、SSH Session 0 の壁を越えられる。
5. **npm @openai/codex の Windows 更新は 224MB の Defender ロック残骸を残す**。稼働 PowerShell では消せない → 再起動時 SYSTEM タスク（Defender 除外を先に追加→削除）で確実に掃除できる（masu-p55 で実証、起動時に `OK-removed (224MB freed)` 確認）。
6. **意図的なガード（読み取り専用 / localhost:1 registry 等）は変更前にユーザー確認**。今回 config.toml 読み取り専用も「remote_control を守る意図的ガードの可能性」を提示してから解除し、副作用（remote_control 削除）も予告どおりだった。
7. **macOS 26.4.1 = M5 機の content-filter × 802.1X Wi-Fi バグ修正**。Apple 系トラブルの一次情報として有用。
