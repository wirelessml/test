#### 🚨 私の誤判定 → 訂正（最重要）

ユーザーの手順に出てきた `②/rc` を、私は「`/model opusplan` の typo / そんなコマンドは無い」と判断し、`~/.claude/commands/` 等を調べて「`/rc` は存在しない」と断定した。**これが誤り**。

- ユーザーが公式記事（dev.classmethod.jp）を提示。`/remote-control`（短縮 `/rc`）は **Claude Code v2.1.53+ の正式機能**だった。
- 私の誤りの原因2つ: ①`/rc` は**ユーザー定義コマンドではなく本体ビルトイン**なので `commands/` に無い ②ユーザー自作の `docs/routines/remote-control-report.md` の `/rc`（DIY 状況報告）と**名前が衝突**していて、そっちと混同した。
- 公式仕様（[code.claude.com/docs/en/remote-control](https://code.claude.com/docs/en/remote-control)）で確定:
  - 既存セッションで `/rc` → ターミナルに**セッションURL**、スペースキーで**QRコード**
  - スマホ側は **Claudeアプリ or ブラウザ claude.ai/code**（claude.ai ログイン必須）
  - 前提: v2.1.53+、**Pro/Max プラン**、`/login` 済み、ワークスペース信頼承認済み
  - 制限: 1セッション1接続 / ターミナル閉じると終了 / 約10分の通信断でタイムアウト / Team・Enterprise 不可（Research Preview）

#### Tailscale 要否の決着

- 仕組みは **Mac →(外向き443)→ Anthropic ←(外向き443)← スマホ の中継**。両端とも**外向き接続**で、inbound を受けないので **Tailscale/VPN/ポート開放は不要（外出先でも）**。公式も「必要なのは Anthropic API への 443 外向き HTTPS だけ」「Claude はローカルで動き続け、クラウドには移らない」。
- ユーザーの「外からだから Tailscale 要る」は **SSH の発想としては正しい**（自宅 Mac に*入る*には inbound 経路が要る）。だが `/rc` は向きが逆。
- ユーザー最終見解: 「`/rc` には不要かもだが、**入れておく派**」＝賢明。理由＝`/rc` の弱点（セッションが落ちると外から `/rc` では復帰不能、新規セッション/tmux/複数同時/素のシェル不可）を **Tailscale+SSH が保険として埋める**。整理: **`/rc`＝普段の楽な経路 / Tailscale+SSH＝保険＋できることの上限**。

## 学んだこと / 気づき

1. **🚨 知らない機能を「存在しない」と断定しない**: `/rc` を commands/ に無い＝存在しないと切ったが、ビルトインは別。知識カットオフ（1月）以降の新機能（v2.1.53+）だった。「調べた範囲で見つからない」と「存在しない」は別。ユーザーがソースを出せる場合は素直に確認する。
2. **名前衝突の罠**: 自作ショートカット（`/rc`=状況報告）と公式コマンド（`/rc`=remote-control）が同名。ドキュメントに明示注記して将来の混同を防ぐ。
3. **`/remote-control` は SSH と「向き」が逆**: SSH は inbound（外から入る→Tailscale 要）、`/rc` は outbound 中継（claude.ai 経由→VPN 不要）。「外からだから VPN 要る」は SSH 限定の直感。
4. **TCC は cron も縛る**: `~/Desktop` 配下のスクリプトは cron から実行不能（Operation not permitted）。死んでいた cron に踊らされない（git log で実績を裏取り）。
5. **今の自分の実行経路は実地確認できる**: `SSH_CONNECTION`/`TMUX`/`who`/プロセス親で、ローカルか SSH か tmux かを断定できる。推測で書かない。
