## ピン留め判断の解決（重要・将来の誤更新防止）

- grep で 5/20・5/25 の「Windows codex 0.130.0 ピン留め」を検出。理由は **0.131+ で `codex remote-control` が Unix 専用化＝Windows native で退行**。
- ただし **6/2 に codex CLI は WSL2（Linux）へ移行済み**（masu-p55.md 変更履歴）。WSL2 では remote-control は壊れないため、**このピン留めは現体制では失効**。現に WSL2 codex は既に 0.141.0 で正常。
- よって canonical codex（WSL2）を最新に保つ判断は妥当。ピン留めは「Windows native remote-control を使っていた旧体制」の遺物。

## 気づき（config ドリフト、今回は範囲外で未修整）

masu-p55 に**二重インストール**が2件。今回はバージョン更新のみのルーチン範囲なので未対応、フラグのみ:

1. **codex が2系統併存**: WSL2 `@openai/codex` 0.141.0（＝canonical・委譲先）と、Windows native codex 0.140.0。docs が記載するのは WSL2 のみ。Windows native は用途不明の遺物（旧 remote-control 由来か）。0.140.0 は既に旧ピン 0.130 を超過済み＝ピンは事実上解除済み。
2. **claude が2系統併存**: SSH で走るのは npm-global（`AppData\Roaming\npm\claude`、今回 2.1.181 へ更新）。別に native（`.local\share\claude`）あり。machines doc は `.local\bin\claude.exe`（standalone・毎日0:00タスクで更新）と記載。`claude update` 実行時に「config expects native / running npm-global」警告→config が global に書き換わった。**毎日の自動更新タスクがどちらを更新しているか要確認**（次回コワーキング時 or 余力時）。
