## ピン留め判断の解決（重要・将来の誤更新防止）

- grep で 5/20・5/25 の「Windows codex 0.130.0 ピン留め」を検出。理由は **0.131+ で `codex remote-control` が Unix 専用化＝Windows native で退行**。
- ただし **6/2 に codex CLI は WSL2（Linux）へ移行済み**（masu-p55.md 変更履歴）。WSL2 では remote-control は壊れないため、**このピン留めは現体制では失効**。現に WSL2 codex は既に 0.141.0 で正常。
- よって canonical codex（WSL2）を最新に保つ判断は妥当。ピン留めは「Windows native remote-control を使っていた旧体制」の遺物。

## 気づき（config ドリフト、今回は範囲外で未修整）

masu-p55 に**二重インストール**が2件。今回はバージョン更新のみのルーチン範囲なので未対応、フラグのみ:

1. **codex が2系統併存**: WSL2 `@openai/codex` 0.141.0（＝canonical・委譲先）と、Windows native codex 0.140.0。docs が記載するのは WSL2 のみ。Windows native は用途不明の遺物（旧 remote-control 由来か）。0.140.0 は既に旧ピン 0.130 を超過済み＝ピンは事実上解除済み。
2. **claude が2系統併存**: SSH で走るのは npm-global（`AppData\Roaming\npm\claude`、今回 2.1.181 へ更新）。別に native（`.local\share\claude`）あり。machines doc は `.local\bin\claude.exe`（standalone・毎日0:00タスクで更新）と記載。`claude update` 実行時に「config expects native / running npm-global」警告→config が global に書き換わった。**毎日の自動更新タスクがどちらを更新しているか要確認**（次回コワーキング時 or 余力時）。

## 追記: masup の二重インストール / 旧 remote-control を解決（同日）

### 調査で判明した全体像
- claude: 正本=standalone（`.local\bin`、毎日0:00 task `Claude Code Update` が `claude.exe update`）。重複=npm-global `@anthropic-ai/claude-code`（PATH を先取り）。両方 2.1.181。
- codex: 正本=WSL2 0.141.0（`codex exec` 委譲先）。重複=Windows-native npm 0.140.0。
- remote-control タスクが**2系統**: `codex-remote-control`（Windows版、`run-codex-remote.bat`→`codex.cmd remote-control`、**codex 0.131+ で Windows 壊れ済み**＝5/20ピン留めの根拠そのもの）/ `CodexWSLRemoteControl`（WSL2版、**PID 148367 で稼働中**）。`codex-watchdog` は無効ゾンビ（6/12処理済）。

### 実施（すべて検証済み）
1. npm-global `@anthropic-ai/claude-code` を uninstall → claude は standalone 単一に（`where claude`=`.local\bin` のみ）。`claude update` で config install method を global→**native へ正常化**（SSH越し更新が一時 global に書換えていたのを是正）。
2. Windows-native npm `@openai/codex`（0.140.0）を uninstall（`where codex`(Win)=なし、WSL2 0.141.0 は温存）。
3. task `codex-remote-control` 削除 ＋ task `codex-watchdog`（無効）削除。
4. `C:\ProgramData\codex-watchdog\` を `C:\Users\gci_admin\codex-watchdog-removed-20260619\` へ退避（バックアップ兼掃除、`Test-Path`=False）。
5. **ガードは追加せず**（Mac も未設定＝足すと逆に不統一。両機とも「claude を npm で入れない」運用で統一）。
6. **WSL2 remote-control（task `CodexWSLRemoteControl`／PID 148367）は意図的に温存**＝ユーザー選択。

## 追記2: おときた駿「ClaudeでPython自動化」ツイート リアリティチェック（fact-checking-x-posts）

対象: https://x.com/otokita/status/2065986307416051881 （6/14、いいね228/24,461view）。本文「ClaudeとPythonで政治ニュース・国会議事録から特定話題を毎日自動で拾って要約する仕組みを30分で作った。チャットで聞きながら作ればコード知識ゼロで可能」。ユーザー指示＝「リアリティチェック」。

**総合判定: ⚠️ 概ね本当**（コア＝「Claude+Python でこの仕組みは作れる」は✅。盛りは「30分・コード知識ゼロ」が"動く初版"の話で、"毎日自動運用に耐える版"の工程を省略している点）。

- ①仕組みの実現性 → ✅ 事実。国会議事録は公式「国会会議録検索システム 検索用API」(kokkai.ndl.go.jp/api.html、JSON/XML・無料・認証不要・HTTP GET、`/api/speech` 等)で機械取得可。既存 MCP/Qiita 実例多数。ニュース=RSS/API、要約=Claude API、毎日=scheduler。**当方の job-search-daily（毎朝04:30 LaunchAgent）が同型を実運用中＝実機で成立確認済み**。
- ②所要30分 → ⚠️ 初版なら妥当。但し本番日次は別物: job-search-daily は6/10だけで5回改訂＋実在/勤務地2段検証、6/12-13 で silent failure（0件でも push/メール、失敗握り潰し）根治、TCC罠でスケジューラ exit126 即死。
- ③コード知識ゼロ → ⚠️ 初版作成は可。詰まるのは環境構築・スケジューラ・**壊れた時のデバッグ**（日次自動化は静かに壊れる: 認証揮発/0件/文字化け/TCC）。
- 補足: おときたは課金煽り系でなく素直な驚き。gap は普遍的な「デモ↔本番」差で、当方が最も知る領域。
